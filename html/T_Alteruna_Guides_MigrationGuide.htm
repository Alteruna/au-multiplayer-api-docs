      Welcome to the Alteruna Multiplayer Migration Guide!

      Who is this for?

      This guide is for developers who already know Photon PUN 2, Photon Fusion, Unity Netcode for GameObjects, or FishNet, and want to know where their existing mental model does - and does not - carry over to Alteruna Multiplayer's Unity SDK (like every guide here, this is about the Unity package specifically, not Alteruna's server or other platform SDKs).
      It assumes you already understand networked identities, RPCs, and state replication in general; it does not re-teach those concepts from scratch. If you are new to multiplayer development altogether, start with the User Guide instead.

      The short version

      Most of what you know transfers directly: identities, RPCs, and replicated fields all have a near-equivalent in Alteruna. The one idea worth unlearning is that a server exists by default. Photon (PUN 2 and Fusion) elects a Master Client or a host, Netcode and FishNet are built around a host or dedicated server process, but Alteruna is peer-symmetric by default - every peer runs identical code, and a dedicated server is an opt-in deployment choice rather than a starting assumption.
      That one difference is why Alteruna also ships a primitive (resource locking) that the other frameworks leave for you to hand-roll.
